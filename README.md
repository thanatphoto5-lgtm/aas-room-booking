# AAS CMU ระบบจองห้อง รุ่น 2.0

เวอร์ชันเชื่อมฐานข้อมูล Supabase สำหรับเว็บไซต์ Netlify เดิม แยก /borrower.html และ /staff.html ไม่มีปุ่มเลือกสิทธิ์เอง ไม่ใช้ข้อมูลการจองจาก localStorage

## สถานะก่อนติดตั้ง
โค้ดและชุด SQL พร้อมติดตั้ง แต่ยังไม่ได้เชื่อมโครงการ Supabase จริงหรือทดสอบกับบัญชีจริง ต้องทำขั้นตอนด้านล่างก่อนเปิดให้บุคลากรใช้ ข้อมูลตัวอย่างจาก DEMO ไม่ถูกย้ายอัตโนมัติ โปรดเก็บไฟล์ส่งออกจาก DEMO ไว้ และตรวจรายการก่อนบันทึกใหม่

## 1. สร้าง Supabase
- สร้างโครงการ Supabase ใหม่ในบัญชีของหน่วยงาน ตั้งรหัสผ่านฐานข้อมูลและเก็บไว้กับผู้ดูแล ไม่ส่งรหัสผ่านในแชตหรือใส่ใน GitHub
- เปิด SQL Editor แล้วรันไฟล์ database/001_schema.sql ทั้งไฟล์ 1 ครั้ง ในโครงการใหม่ สคริปต์สร้างโครงสร้างและทำงานใน transaction หากผิดพลาดจะย้อนกลับทั้งหมด ไม่ต้องรันซ้ำหลังติดตั้งสำเร็จ
- ตารางอยู่ schema booking_private ซึ่งไม่ควรถูกเพิ่มใน Exposed schemas ของ Data API ให้คง public ตามเดิม
- ค่าความจุ MTR2 30 คน และ AB2-003 60 คน เป็นตัวอย่าง ต้องแก้ให้ตรงห้องจริงผ่าน SQL Editor ก่อนเปิดใช้:
  `update booking_private.rooms set capacity = จำนวนจริง where id = 'MTR2';`

## 2. การเข้าสู่ระบบและบัญชีผู้ใช้
- เปิด Email/password authentication ใน Supabase เปิดการสมัครตามขั้นตอนสำหรับผู้จองทั่วไปด้านบน
- ตั้งรหัสผ่านขั้นต่ำ 12 ตัวอักษรใน Supabase ให้สอดคล้องกับแบบฟอร์ม
- Authentication → URL Configuration: Site URL เป็น URL Netlify จริง และ Redirect URLs เพิ่ม `https://ชื่อเว็บ.netlify.app/login.html` แบบเจาะจง ไม่ใช้ wildcard กว้าง
- ตั้งค่า Custom SMTP ของหน่วยงานและทดสอบส่งอีเมลก่อนเปิดใช้จริง อีเมลเชิญ/กู้รหัสผ่านต้องพึ่งบริการอีเมลของ Supabase ที่ตั้งค่าไว้
- ผู้ดูแลบัญชี Supabase เพิ่ม/เชิญผู้ใช้ใน Authentication → Users โดยตั้ง redirect ไป /login.html ผู้ใช้ตั้งรหัสผ่านเองจากลิงก์ invite ห้ามใช้รหัสผ่านร่วมกัน
- บัญชี Auth เพียงอย่างเดียวยังเข้าใช้งานไม่ได้ ต้องเพิ่มใน booking_private.members ด้วย SQL ตัวอย่างด้านล่าง (เปลี่ยนอีเมลและชื่อจริง):

```sql
insert into booking_private.members(user_id,name,staff)
select id, 'ชื่อ นามสกุล', false from auth.users where lower(email)=lower('user@cmu.ac.th')
on conflict(user_id) do update set name=excluded.name, active=true;
```

- สำหรับเจ้าหน้าที่ เปลี่ยน false เป็น true ในการเพิ่มครั้งแรก หากมีสมาชิกแล้ว ให้ผู้ดูแลรัน:

```sql
update booking_private.members set staff=true
where user_id=(select id from auth.users where lower(email)=lower('staff@cmu.ac.th'));
```

- ระงับสิทธิ์ทันที: update booking_private.members set active=false where user_id='UUID'; ตรวจผล affected rows เพื่อยืนยัน
- ผู้จองไม่สามารถให้สิทธิ์ตนเองได้ทั้งจาก UI และ API การเปลี่ยนชื่อ/บทบาททำผ่านผู้ดูแล Supabase เท่านั้น

## 3. อัปเดต GitHub และ Netlify
- อัปโหลดเนื้อหาแพ็กเกจนี้ที่ root ของ repository aas-room-booking เดิม แทนที่ไฟล์ชื่อเดิม พร้อมโฟลเดอร์ database, scripts, assets, vendor, tests
- index.html เดิมถูกแทนด้วยหน้าเข้าสู่ระบบ ห้ามนำ demo app.js กลับมาใช้กับรุ่นนี้
- Netlify → Project configuration → Environment variables เพิ่ม (ใช้กับ build):
  - SUPABASE_URL = Project URL เช่น https://xxxxxxxx.supabase.co
  - SUPABASE_PUBLISHABLE_KEY = publishable key (`sb_publishable_...`) หรือ legacy anon key
- ห้ามใช้ service_role หรือ sb_secret_... ระบบ build จะปฏิเสธ key ที่เป็นความลับ Public key ไม่ใช่ตัวกำหนดสิทธิ์: ฐานข้อมูลตรวจ JWT และ allowlist ทุกคำขอ
- Build command: npm run build
- Publish directory: dist (เปลี่ยนจาก . ของ DEMO)
- Base directory: เว้นว่าง
- netlify.toml ในแพ็กเกจระบุค่าตั้งค่าใหม่แล้ว เมื่อเพิ่ม environment variables ให้ Redeploy
- build สร้าง config.js เฉพาะค่า public และ CSP จำกัดการเชื่อมต่อที่ Supabase โครงการนั้น ไม่เผยแพร่ SQL/ชุดทดสอบใน dist

## 4. URL สำหรับใช้งาน
- /login.html เข้าสู่ระบบ
- /borrower.html หน้าผู้จอง: ปฏิทินรวมทุกห้อง จอง ติดตามและยกเลิกของตัวเอง
- /staff.html หน้าเจ้าหน้าที่: ตรวจคำขอ อนุมัติ ไม่อนุมัติ จัดการห้อง นำเข้าเรียน รายงาน และประวัติ
- เปิดลิงก์เจ้าหน้าที่โดยบัญชีผู้จองจะถูกปฏิเสธ เจ้าหน้าที่สามารถเปิดหน้าผู้จองผ่าน URL ได้
- session เก็บใน sessionStorage ของแท็บ การจองเก็บบน Supabase ส่วนกลาง โหลดข้อมูลใหม่ทุก 30 วินาทีขณะเปิดแท็บ หรือกดโหลดข้อมูลล่าสุด
- เบอร์โทร หน่วยงาน หมายเหตุ และเหตุผลยกเลิก ส่งจากฐานข้อมูลเฉพาะเจ้าของรายการกับเจ้าหน้าที่ สมาชิกคนอื่นเห็นชื่อกิจกรรม/ห้อง/เวลา/สถานะ

## 5. ตารางเรียน
ดาวน์โหลด AAS_Schedule_Template.xlsx กรอก 6 คอลัมน์เดิม: รหัสวิชา, ชื่อวิชา, ห้อง, วันเรียน, เวลาเริ่ม, เวลาสิ้นสุด เลือกภาคเรียนและวันยกเว้น ตรวจตัวอย่างก่อนยืนยัน รองรับ Excel/CSV 5 MB 500 แถว และไม่เกิน 10,000 คาบต่อคำขอ ใช้เวลา 08:00–18:00 และคาบที่เริ่มในอนาคตเท่านั้น
การแทนที่ตารางเดิมจะยกเลิกคาบเดิมและเพิ่มชุดใหม่ใน transaction เดียว หากมีรายการชนกันทุกส่วนจะย้อนกลับ คาบเดิมยังอยู่ รายการจองประชุมไม่ถูกแทนที่

## 6. ตรวจรับก่อนเปิดจริง
1. บัญชีผู้จอง A และ B อยู่คนละเบราว์เซอร์ เห็นรายการเดียวกันเมื่อโหลดล่าสุด
2. A ส่งคำขอ; B จองห้องและเวลาเดียวกันต้องถูกปฏิเสธ รวมถึงกดพร้อมกันจากสองเครื่อง
3. ผู้จองเปิด /staff.html ต้องเข้าไม่ได้ และเรียก API approve/room/import โดยตรงต้องไม่ได้
4. ผู้จอง B ต้องไม่เห็นเบอร์โทรหรือหมายเหตุของ A แม้ดู response ของ API
5. เจ้าหน้าที่อนุมัติ/ไม่อนุมัติพร้อมเหตุผล; A เห็นผลหลังโหลดล่าสุด
6. A ยกเลิกของตัวเองได้ แต่ยกเลิกของ B ไม่ได้
7. ทดลองนำเข้าชุดตารางที่ชนกัน ต้องไม่มีข้อมูลบางส่วนถูกบันทึก
8. ทดสอบอีเมล invite, recovery, token หมดอายุ, logout และระงับสมาชิก
9. ตรวจชื่อห้อง ความจุ ผู้ดูแลบัญชี และแผนสำรองข้อมูลของโครงการ

## การทดสอบที่รันแล้ว
- การตรวจไวยากรณ์ JavaScript และ core tests เรื่องเวลา/วันหยุด/ซ้อนกัน/การวางรายการ
- tests/database.mjs: PostgreSQL ผ่าน PGlite ใช้ auth.uid จำลองเพื่อทดสอบตรรกะ SQL และสิทธิ์ฐานข้อมูล 23 กรณี
- ยังไม่ได้ทดสอบบัญชี/อีเมลจริง เครือข่ายจริง หรือ concurrency ผ่าน Supabase จริง เพราะยังไม่ได้เชื่อมโครงการ การป้องกันเวลาใช้ native exclusion constraint ของ PostgreSQL
- รันเอง: npm ci แล้ว npm test และ npm run test:database

## การดูแลข้อมูล
JSON/CSV เป็นไฟล์ส่งออกรายงาน ไม่ใช่ full database backup ไม่มีปุ่มเขียนทับฐานข้อมูลจากไฟล์ DEMO สำรอง/กู้คืนฐานข้อมูลตามบริการของโครงการ Supabase โดยผู้ดูแล บันทึก audit ทุก mutation สำเร็จ; ไม่เก็บรหัสผ่านในฐานข้อมูลแอปหรือโค้ด

## รายงานและจอมอนิเตอร์
หน้าเจ้าหน้าที่ → รายงาน → รายงานรายวัน เลือกวันและห้องแล้วกดแสดงผลหรือพิมพ์ เปิดจอมอนิเตอร์รายวันที่ /monitor.html เลือกห้องแล้วกดเต็มจอ ใช้วันที่ประเทศไทย แสดงเฉพาะรายการยืนยันและคาบเรียน โหลดทุก 30 วินาที หมุนหน้าละ 4 รายการทุก 10 วินาที เครื่องจอใช้บัญชีเจ้าหน้าที่ที่เข้าสู่ระบบแล้ว
