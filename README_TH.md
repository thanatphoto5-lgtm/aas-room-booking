# ระบบจองห้อง AAS CMU รุ่น 3 — GitHub + Netlify

ผู้จองเปิดเว็บแล้วจองได้ทันที เจ้าหน้าที่กรอกรหัสผ่านกลางอย่างเดียว
ข้อมูลส่วนกลางเก็บด้วย Netlify Blobs ผ่าน Netlify Functions

## ติดตั้งในเว็บไซต์เดิม

1. แตกไฟล์ ZIP แล้วอัปโหลดไฟล์และโฟลเดอร์ทั้งหมดภายในลงที่หน้าแรกของ repository `aas-room-booking` ใน GitHub ให้แทนที่ไฟล์ชื่อเดิม อย่าอัปโหลด ZIP หรือครอบด้วยโฟลเดอร์อีกชั้น
2. ต้องมี `package.json`, `package-lock.json`, `netlify.toml`, `server/`, `netlify/functions/`, `scripts/` และไฟล์หน้าเว็บในระดับเดียวกันตามชุดนี้
3. ใน Netlify เปิด Project configuration → Environment variables → Add a variable
4. ใส่ Key เป็น `STAFF_PASSWORD` และ Value เป็นรหัสผ่านเจ้าหน้าที่ที่คุณกำหนด อย่างน้อย 12 ตัวอักษร แนะนำวลีที่คาดเดายาก ใช้ Same value for all deploy contexts และ All scopes หรือ scope Functions หากมีให้เลือก
5. บันทึก แล้ว Deploy ใหม่ให้ขึ้น Published ใช้ Build command `npm run build` และ Publish directory `dist` ตาม netlify.toml
6. เปิดหน้าเว็บหลักเพื่อจอง เปิด `/login.html` เพื่อเข้าสู่ระบบเจ้าหน้าที่ด้วยรหัสที่ตั้งไว้

การเปลี่ยนรหัสให้แก้ค่า STAFF_PASSWORD ใน Netlify แล้ว Deploy ใหม่
รหัสอ่านโดยฝั่งเซิร์ฟเวอร์และไม่ถูกเขียนลงไฟล์เว็บหรือ GitHub
หากลืมรหัส ผู้ดูแลโครงการ Netlify สามารถเปลี่ยนค่าได้

## การใช้งาน

- หน้าแรกและ `/borrower.html` เป็นหน้าผู้จอง
- `/staff.html` ต้องผ่านรหัสเจ้าหน้าที่และการตรวจสิทธิ์จากเซิร์ฟเวอร์
- `/daily.html` รายงานรายวัน และ `/monitor.html` จอมอนิเตอร์รายวัน ใช้สิทธิ์เจ้าหน้าที่
- เจ้าหน้าที่อนุมัติ ปฏิเสธ ยกเลิกคำขอ เพิ่มห้อง และนำเข้า Excel ตารางเรียนได้
- รหัสกลางเป็นบัญชีร่วม ประวัติการทำงานจะแสดงชื่อ “เจ้าหน้าที่”
- สิทธิ์เจ้าหน้าที่หมดอายุใน 8 ชั่วโมง ต้องกรอกรหัสอีกครั้ง หลังเปลี่ยนรหัสและ Deploy ใหม่ สิทธิ์เก่าจะใช้ต่อไม่ได้
- ผู้จองติดตามและยกเลิกรายการของตนผ่านเบราว์เซอร์เดิม โดยตัวระบุผู้จองมีอายุ 30 วัน การล้างคุกกี้ เปลี่ยนเครื่อง หรือออกจากระบบ จะทำให้เข้ารายการส่วนตัวเดิมไม่ได้ ให้ติดต่อเจ้าหน้าที่ช่วยจัดการ
- ปฏิทินส่วนกลางแสดงรายการที่มีการจอง โดยข้อมูลติดต่อเปิดให้เจ้าของรายการและเจ้าหน้าที่เท่านั้น
- จองได้ 08.00–18.00 น. ในอนาคตไม่เกิน 2 ปี ผู้จองหนึ่งรายมีรายการรออนุมัติได้ 5 รายการ
- การเข้ารหัสผิดหรือถูกนับรวมสูงสุด 10 ครั้งต่อ 15 นาทีต่อ IP เพื่อจำกัดการเดารหัส
- สามารถดาวน์โหลด JSON สำรองข้อมูลและ CSV รายงานได้ในหน้าเจ้าหน้าที่

## ข้อมูลเริ่มต้นและการเปลี่ยนรุ่น

ระบบเริ่มด้วยห้อง MTR2 (30 ที่นั่ง) และ AB2–003 (60 ที่นั่ง) ตามข้อมูลตั้งต้นของชุดก่อนหน้า โปรดตรวจความจุกับห้องจริงก่อนใช้งาน

ชุดนี้สร้างคลังข้อมูลใหม่ชื่อ `aas-booking-v3` ในโครงการ Netlify เดิม ข้อมูลเดิมใน Supabase หรือ localStorage ของชุดทดลองไม่ได้ย้ายอัตโนมัติ หากมีรายการเดิมที่ต้องเก็บ ให้สำรองออกมาก่อนเปลี่ยนรุ่นและจัดเตรียมการนำเข้าข้อมูลนั้นแยกต่างหาก

ไฟล์ฐานข้อมูล SQL และค่าตัวแปร SUPABASE เดิมจะไม่ได้ถูกเรียกใช้โดยชุดนี้
Netlify Blobs ใช้คลังข้อมูลระดับเว็บไซต์ ข้อมูลคงอยู่เมื่อ Deploy ใหม่ในเว็บไซต์เดิม การสร้าง Netlify site ใหม่จะใช้คลังข้อมูลแยกกัน
การใช้งาน Functions และ Blobs เป็นไปตามโควตาของบัญชี Netlify

## การตรวจสอบก่อนเริ่มใช้จริง

1. เปิดเว็บจากหน้าต่างส่วนตัว ตรวจว่าหน้าจองแสดงทันที
2. เปิด `/staff.html` ต้องพาไปหน้ารหัสผ่าน ลองรหัสผิดแล้วรหัสถูก
3. จองเวลาที่ยังว่างจากอีกเบราว์เซอร์ แล้วอนุมัติจากหน้าเจ้าหน้าที่ ตรวจว่าข้อมูลตรงกัน
4. ลองจองห้องเดียวกันเวลาเดียวกัน ระบบต้องปฏิเสธ และลองคนละห้องเวลาเดียวกันต้องทำได้
5. เปิดรายงานและจอมอนิเตอร์ ทดสอบออกจากระบบแล้วเข้า staff อีกครั้ง

ตรวจโค้ดด้วย `npm ci` และ `npm run build`
ชุดทดสอบใช้คลังข้อมูลจำลอง ทดสอบสิทธิ์ ความเป็นส่วนตัว รหัสผิด/ถูก การหมดสิทธิ์หลังเปลี่ยนรหัส การจำกัดคำขอ การชนกันของการจองพร้อมกัน การลองซ้ำ และการย้อนกลับเมื่อการนำเข้าไม่สำเร็จ ต้องตรวจการเชื่อมต่อ Netlify จริงหลังเผยแพร่
